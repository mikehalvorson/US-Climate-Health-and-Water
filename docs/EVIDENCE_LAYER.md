# Canonical evidence layer

## Purpose

Step 3 converts the immutable, tracked research corpus into one deterministic
registry store for application code. The generated layer preserves the
research package's native identities and evidence limits; it does not edit the
research files or fill missing values.

Run the adapter with:

```powershell
pnpm generate:registries
```

`pnpm generate:check` reproduces every generated byte in memory and fails when
the committed artifacts are stale.

## Identity and collision policy

[`id-map.json`](../src/data/registry/id-map.json) is the stable mapping from
legacy identities to canonical six-digit namespace IDs. Existing assignments
are reused on every run. A semantic hash records the canonical record meaning
and feeds the semantic-drift report.

Twenty-five legacy source IDs have definitions in more than one domain file.
The adapter resolves them with an explicit owner-precedence list: top-level
domain source registries precede module verification and access catalogs. The
selected path, every candidate path, and the number of metadata variants are
published in
[`registry-audit.json`](../src/generated/registry-audit.json). There are no
unresolved source references in this corpus; a future orphan will become a
pending source placeholder and a linked open item instead of disappearing or
receiving invented metadata.

## Status and fidelity rules

- A source is active only when its identity is verified and it has an access
  date, publisher, title, and canonical URL.
- A claim is active only when its fidelity and publication status are verified,
  its confidence is assessed, and all supporting sources are active.
- A metric is active only when its sources and claims are active and its value,
  unit, period, geography, evidence state, and accounting boundary are explicit.
- Source scenarios remain conditional and separate by model family. They are
  never converted into forecasts or probability intervals.
- Nulls remain null. Pending strategy parameters have no numeric defaults and
  participate in validation only.
- Population or household rates require an active canonical denominator before
  they can become active.

The TypeScript guardrails also check confidence propagation, natural/base/stress
bounds, currency vintage, interval overlap, use class, geographic cardinality,
and exact foreign-key resolution.

## Published gaps and manifests

The open-item registry includes all 86 research gap records, four grouped
evidence/implementation gaps, and twelve parameter-specific model gaps. Each
item names affected canonical outputs, ownership, blocking conditions, and the
next action.

[`registry-manifest.json`](../src/generated/registry-manifest.json) records a
SHA-256 checksum for all 209 tracked research inputs and each generated output.
[`registry.json`](../src/generated/registry.json) is the application-consumable
registry store. Application modules must import the canonical store rather than
read research files or create local identities.
